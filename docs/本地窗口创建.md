# 本地窗口创建

当前本地开发版增加“新建窗口”“批量创建”，没有启用比特云端创建或资料同步。旧窗口的来源导入、原指纹、加密资料、代理门禁和删除流程继续沿用。尚未发布本轮改动。

## 功能与边界

| 设置 | 本地实现 |
|---|---|
| 单个/批量 | 每批1–1000个，名称前缀加序号；逐项提交，可取消后续、恢复中断、重试失败项 |
| 内核 | 21个已适配精确构建；仅已部署的内核能直接离线使用，缺少时从本机合法库存部署，不猜未知build |
| 基础信息 | 名称、分组、标签、备注、平台、用户名、密码、2FA密钥、多开兼容值、重复平台用户名校验、启动网址 |
| Cookie | JSON、请求头、Netscape文本；包含HttpOnly、会话或到期Cookie，首次启动先注入再访问账号页 |
| 代理 | HTTP、HTTPS、SOCKS5、密码认证SSH；空批量代理沿用设置、1行共用、N行与N窗口一一对应 |
| 动态代理 | 可选提取链接，每次打开提取唯一代理，支持文本及常见JSON封装；10秒进程预算、64KiB上限、不跟重定向、不读取系统代理，失败不直连 |
| 指纹 | 新建时选择设备、OS、内核、UA/Client Hints、CPU、内存、语言、时区、位置、分辨率、字体、Canvas/WebGL/Audio/Rects、WebRTC、媒体/语音/插件、设备标识、端口、TLS及高级参数 |
| 随机 | 一键随机；批量可选同指纹或每窗独立；随机结果在任务登记时固定。默认正常重开不随机 |
| 偏好 | 静音、GPU、通知、图片/媒体、剪贴板、账号登录、密码保存、翻译、内存节约及标签恢复 |
| 新建专属选项 | 按IP匹配语言/界面语言/时区/位置、每次打开随机、IP/国家变化停止、后台模式、图片大小阈值、IP页开关、显式清理缓存/Cookie/历史 |

默认使用手动固定环境、位置询问、无启动清理。按IP匹配需要从当前代理取得完整信息，失败明确报错，不猜位置。每次随机只在显式开启后进行，保留原DataProtect和OSCrypt密钥；变动的环境仍需重新通过后台基线验证。已导入的原有窗口不进入这些流程。

清Cookie会丢失对应网站登录，随机环境也可能引发平台重新验证。默认均关闭；保存登录不能代替平台自身的有效期规则。SSH首次连接按窗口和地址固定公开主机密钥，后续变化拒绝；密钥记录随窗口永久删除。后台模式只允许浏览器本来会保留的后台进程继续运行，不增加常驻服务。

与原厂仍有明确差别：不使用其云端代理商购买/托管和团队权限服务；不提供二维码图片识别（2FA可直接填密钥）；没有SOCKS5 UDP；网络异常停止保持此前要求的10秒强制门禁，不能通过开关绕过。额外跨系统字体文件不自动下载，随机/自定义字体仅接受本机可用字体。原厂随机样本分布无法由静态分析证明完全相同，不能把本地样本库描述为完整原厂随机服务。

## 实现

`creation_fingerprint.py`读取约100KiB公开参数库，使用原厂已提取的配置转换函数和现有本地签名器生成原生载荷。UA完整版本固定为实际已适配build。新窗口各自生成OSCrypt密钥，130及更新内核还各自生成DataProtect密钥；同指纹批量也不共享资料密钥。

干净便携包首次部署内核时，优先通过`EngineStore.resolve`完整校验对应随包原始库存，再以当前目录的签名根部署独立副本；存在但损坏的随包库存拒绝使用。只有该版本库存目录不存在时才沿用原厂库存发现路径，已认证的既有归档映射仍优先。默认包带148，因此该版本首次创建不要求本机装有比特或其数据库。

新建指纹使用已核实的原厂7.2.0服务端创建默认噪声例外规则；两份独立新建样本的Canvas/WebGL各33条规则及有序摘要一致，保留原通配匹配语义。这是该版本的默认快照，不声称所有账号或未来版本永远相同。只有首次本地创建使用模板；已导入窗口及已有本地窗口保留原有规则，不因重算随机指纹而套用新模板。

新创建时按实际内核和完整UA取得Google公开签名运行种子，验签后写入独立加密缓存；同内核同UA再次创建可离线命中。首次缺少缓存时需要联网，失败不提交窗口。缓存最多32项、8MiB，逐次验签，无后台更新；既有窗口继续用原载荷中的种子。原来缺少种子的旧本地窗口不自动补写，避免改变其环境基线。

切换新建的移动设备类型时，采用原厂公开屏幕字典（Android 11项、iOS 6项）、500×950窗口及相应DPR；仅在明确切设备时重置，随后手动设置会保留。创建时随机分辨率使用相应设备字典，同指纹批量只选一次。首次正式打开应用所填窗口尺寸，成功后消费该一次性设置；此后关闭重开使用浏览器保存的窗口状态。

WebRTC替换模式即使其他按IP匹配项均关闭，也会按实际代理采样出口；真正打开前再次通过浏览器所用转发门禁核对，无法核实或出口变化则拒绝。该路径只作用于本地新建窗口。剪贴板权限在关闭状态按原厂启动设置准备，保留无关资料和恢复备份；签名维护先于新建窗口的环境重算，避免到期或时钟回拨阻断维护。

未显式禁用剪贴板的新建窗口首次保留原生询问状态；第一次成功打开后，再次开窗按原厂成熟资料的启动逻辑准备允许设置。显式禁用从首次即生效，已导入窗口仍按其保存的开关处理。空位置不伪造0坐标，纬度/经度为null，未填写的精度字段保持缺失；明确填写的0仍是有效值。

`window_create.py`登记`creation_jobs/creation_items`。请求ID与规范化配置摘要绑定，同ID同配置返回原任务，同ID不同配置拒绝。待处理配置加密，成功或取消后清除；队列随机值固定后重试，不凭窗口名或序号匹配资料。创建、同步、删除共用工作租约，逐项复用`import_intents`认证暂存、完整摘要、发布和不确定提交恢复，已提交绑定不会重复创建。

每个窗口使用独立空profile完成后台环境登记和再次验证，成功后才发布。前端只显示计数及尾100条结果，使用版本号保护取消、恢复、bootstrap和轮询。永久删除同时清理创建关联、签名、资料、代理主机密钥及原有受管恢复副本。

随机字体留空时，字体子集也在创建任务登记时固定并加密保存：同指纹批量只选一次，独立模式逐项选择；创建失败、恢复及重试沿用该选择。旧版未固定字体的待处理项在首次创建前先持久化选择；旧任务没有保存批量模式，不能追溯恢复其原本未登记的共同选择，不修改已完成窗口。显式字体和默认系统字体不进入此抽样。

功能开发新增的运行依赖为`tzdata 2026.6`（为Windows提供IANA时区）和按需加载的AsyncSSH。0.2.0发布候选已将`asyncssh`锁定为`2.24.0`以修复已知漏洞，发行环境沿用v0.1.0干净环境的依赖锁并校验匹配；这不表示用户现用的旧`runtime`已被自动升级。没有前端框架或新增常驻服务。公开样本通过正常会话读取后按字段白名单整理；产品资源不含账号/代理凭据，也不依赖研究目录。

## 研究和验证证据

REA CLI已实际分析原厂`app.asar`及选择性主进程/渲染模块，主证据ID为`ev_7c3c7b513cd91683bc0c6ffcfc237ed35eb88719b0e29794fd5aaa3792e699af`。原厂远程创建界面分为基础、Cookie、代理、常用、指纹；单个和批量共用表单，批量上限1000。报告保留在`analysis/reports/creation-rea-*.json`。静态分析不能证明所有运行路径；归档中已有ssh2辅助文件的完整性差异已记录，不能当作整个原厂包已验收。

已评估`browserforge`、`python/tzdata`和`ronf/asyncssh`：选择原有原生配置流程，不引入另一套指纹注入；SSH复用成熟AsyncSSH。许可证见根目录第三方声明。

- `creation-all-cores-live.json`：21个内核各完成新建、46项后台基线、两次正式打开/关闭、完整删除；另外3个批量窗口的噪声和资料密钥各自独立，全部删除。
- `creation-options-live.json`：最终默认及启动选项在104/148上实测；动态代理、按IP匹配时区、每次随机均生效，两次开窗Cookie和LocalStorage保留，DataProtect与OSCrypt密钥不变。
- `test_window_creation.py`、`test_ssh_proxy.py`、`test_dynamic_proxy.py`及前端状态测试加入默认自检：覆盖幂等、中断、取消、绑定、坏密钥/认证、提取超时、迟到状态和原窗口隔离。
- `verify_clean_start.py --execute`：实际显示无用户资料的干净管理器，确认页面及桥接就绪并正常退出。
- `creation-ui-live.json`：真实WebView中点击批量创建、切换系统/内核、提交两个窗口、查看完成进度和列表，再完整删除本次窗口，所有检查通过。

以上浏览器测试只使用带明确标记的隔离程序副本和合成账号资料。没有用真实平台账号测试创建后的换机，也没有把本机验证宣称为新窗口已通过第二台设备验收；原有148跨设备规则保持原范围。
