# 0.2.2换机和移动盘兼容修复

本文记录0.2.2历史包的功能与测试范围，下面补充纠正换机操作。当前目录后续修复不会自动进入已生成的0.2.2 ZIP，也不代表该历史包已重新测试或重新打包。

本文提到的旧完整迁移工具已停用，以下操作仅保留为历史记录。当前升级方式为完整新版包覆盖原目录后正常启动，见[原地更新](原地更新.md)。

原电脑桌面能够打开，不代表资源管理器已经把全部文件复制到另一台电脑。8.3短路径属于目标磁盘环境，不能作为便携迁移的必要条件。

| 现象 | 原因及本版处理 |
|---|---|
| 移动盘打开提示层级过深、没有可用短路径 | 旧部署两层64字符标识造成目录膨胀。本版将路径标识缩为16字符前缀，完整身份和校验仍保存在清单；旧内核经过完整认证后复制升级，原目录保留 |
| 复制PrivacySandboxAttestationsPreloaded等目录提示目标路径太长 | 使用根目录“完整迁移到新目录.cmd”，通过Windows扩展长度路径复制并逐文件校验，不经过资源管理器的逐项跳过流程 |
| 复制_platform_specific等目录提示目标路径太长 | 同上；所有文件、隐藏文件、空目录和资料密钥一并核对。目标仍应是尚不存在的短目录，过深目标在复制前拒绝 |
| 跳过文件后提示独立内核校验失败 | 该副本已缺件，不能降低校验继续使用。工具在正式发布目标前认证来源内核及全部文件，失败不发布，源原件不修改。必须回仍能正常打开的原电脑完整目录重新迁移 |

## 正常带资料换机（操作更正）

完整且已带资料的便携目录应一并携带运行环境、内核、配置、资料和密钥。正常关闭原电脑全部浏览器窗口及管理器后，将整个目录完整复制到新电脑或移动盘的合理短路径，再直接双击包内 **启动本地浏览器.cmd**。新电脑不需要旧资料或比特客户端，不需要先运行迁移工具；从移动盘复制到本机也采用相同步骤。

0.2.2发行ZIP是干净程序包，不含你的账号资料、代理凭据或旧密钥；仅解压它不会带来原有账号。带资料便携目录与干净发行ZIP是不同交付物，不应混用。

旧长内核转换后仍保留原长目录，复制整个目录时仍可能遇到路径过长。新电脑首次启动无法解决复制之前的失败或跳过的文件，须在原电脑先准备并校验可完整复制的整理副本。0.2.2迁移工具整树保留旧目录，没有一键去除旧长布局的功能；不能将它描述为已完成整理，也不能保证任意深路径可复制或启动。

## 原电脑可选维护复制

以下是0.2.2工具的维护复制流程，用于需要升级或逐文件校验的情况，不是新电脑正常启动步骤：

1. 回原电脑，确认原完整目录仍在。正常关闭全部浏览器窗口和管理器。
2. 解压0.2.2干净程序包到短目录；不要覆盖旧程序，不要先启动空管理器。
3. 双击新版 **完整迁移到新目录.cmd**，来源填原来能正常打开的旧目录，目标填一个尚不存在的短目录，例如移动盘的`D:\LB`。工具按全部旧内核文件树检查目标长度，不依赖新电脑开启长路径；若提示目标过深，直接改用盘符根目录下的短文件夹。等待“迁移完成，全部文件已校验”。原目录作为备份保留。
4. 完成后保留原目录作为备份，核对目标完整性。对于路径已适合完整复制的带资料目录，到新电脑后直接从目录内启动；不要再把迁移工具列为必经步骤。

工具不会上传资料，不重建旧密钥，不更换账号指纹，不延长Cookie期限。来源关闭状态、签名、内核、目标空间、源前后稳定性和每个复制文件均检查；取消、超时或失败保留目标旁未完成副本，不能把它当正常目标使用。

该工具覆盖已有便携格式。资料丢失、密钥缺失、来源已经跳过文件，或目标系统/文件系统本身不支持某类文件时仍会明确拒绝，不会伪造恢复成功。原厂环境差异规则及真实账号跨设备登录的验收边界继续保留；本机模拟不能代替第二台实体电脑的实际账号验收。

完整步骤见[便携升级与实体机测试](便携升级与实体机测试.md)。
