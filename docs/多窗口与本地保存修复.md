# 多窗口与本地保存修复

## 原因和修复

本次复现的退出是内核主进程异常终止，退出码为`0xC0000409`，不是管理器主动关闭。原厂内核和独立内核使用相同原生指纹载荷进行对照，只有独立内核在几十秒后退出。启动时的短测试不足以发现这个问题。

精确构建除静态公钥块外，资源包内还有独立编码的公钥，供延迟校验使用。旧部署漏了这一路。本次补齐21个已支持构建的资源公钥；保持校验执行，不修改返回值、关闭安全检查或修改指纹。`core_specs.py`固定每个精确构建的资源包摘要、成员位置和公钥跨度，`local_engine.py`只替换对应294字节。还原公钥后必须得到固定的原厂资源包摘要，并重新验证整个来源树。

修复部署为同级`-r2`目录，旧构建保留。来源和副本均完整校验，暂存验证完成才发布；普通打开会自动选择修复后的构建。连续性校验先验证修复的字节证明，再使用与旧部署相同的规范化清单摘要。因此已有指纹、OSCrypt钥匙和原环境基线都不需要重新生成。

另一处问题是原生偏好仍标记上次`Crashed`，浏览器读取到会话文件后仍可能不自动恢复。`session_recovery.py`在有可读原生会话时，先原子备份Preferences、Sessions、Session Storage，再处理退出标记；原始导航记录和Session Storage交给原内核恢复。备份只保留当前一份，位于该profile内的`.local-session-recovery.zip`，会随窗口彻底删除。它不是完整浏览器备份，也不会自动覆盖现有资料。

恢复会话继续使用原生启动开关，不直接修改受保护的启动页偏好。Cookie补写另修复了部分内核在未分区Cookie上也保存ancestor位的差异；只在存在top-level site时将该位用于分区认领，不给会话Cookie增加有效期，不重新回放已导入窗口的旧Cookie。

## 本地保存

浏览器直接使用每个窗口的独立资料夹运行。新增/关闭标签由原内核写Sessions，网站数据写Cookie数据库、Local Storage、Session Storage和IndexedDB。这里不需要云端同步，也不需要在关闭后另复制一次资料夹。

没有添加轮询网站、注入页面脚本、账号重新登录或重建页面URL列表的替代保存机制。正常关闭继续等待原生进程完成落盘；不会强行结束仍在保存的浏览器。操作系统崩溃或断电时，最后尚未落盘的瞬间改动仍受原内核和文件系统的限制。

104内核的后台标签采用原生延迟加载，激活前可能还没有调试目标。不能把一次`Target.getTargets`没有列出该页视为资料丢失。隔离专项通过原生标签切换激活后再核对网页及Session Storage；产品保留原来的延迟加载行为。

## 启动开销

`engine_validation.py`只在单次打开期间复用摘要。Windows只读共享句柄阻止文件写入和替换，每次校验仍枚举完整文件树，操作结束立即释放所有句柄。已有写入句柄的文件不缓存，跨次打开不复用。静态还原验证同样受这些句柄约束。回环控制接口改用标准库HTTPConnection，避免每次本地HTTP请求重新初始化无关的HTTPS上下文。

同一合成148窗口原完整打开约9.5–10秒，修复后单独测试约6.2–7秒；大量磁盘复制、并行测试和真实代理网络会影响实测，不据此承诺固定启动时间。线程、批量开窗顺序、代理门禁和环境探针规则未改变。

## 证据与维护

- `analysis/reports/native-duration-comparison.json`：相同原生载荷的原厂/旧独立运行对照。
- `analysis/reports/native-resource-roots.json`：21个构建的资源根发现结果；仅含公开制品位置和摘要。
- `analysis/reports/native-duration-resource-fixed.json`：补齐资源根后的24小时/10年签名对照，均持续100秒正常运行。
- `analysis/reports/multi-window-persistence.json`：4窗口持续运行、多标签增删、本地文件落盘及两次重开，验证Cookie、Local Storage、Session Storage、IndexedDB和最新登录值不回退。
- `analysis/reports/window11-session-recovery.json`：仅使用关闭资料副本恢复原5个页面，两轮重开，来源关键文件摘要未变。
- `analysis/reports/all-core-cookies-after-delayed-fix.json`：各精确构建的两轮原生Cookie回归。
- `analysis/reports/mixed-core-local-save.json`：104、124、148、156混合运行，激活旧内核后台标签后核对恢复数据，再保存新的模拟登录值并重开验证。
- `tests/test_session_recovery.py`、`analysis/local-engine-tests.py`覆盖原子失败、旧基线保持、资源篡改拒绝和校验缓存的句柄释放。

原始制品的动态调试与只读反汇编证据保留在`analysis/`，不是REA MCP Evidence记录。资源包索引解释参考Chromium BSD源码的`tools/grit/grit/format/data_pack.py`；会话格式参考`components/sessions/core/command_storage_backend.cc`和`session_service_commands.cc`。产品没有引入这些库或新的依赖。

后续新增精确构建，必须同时核实静态公钥块和资源公钥，并加入超过延迟校验周期的运行测试；验收还应恢复非活跃标签，检查Session Storage和更新后的Cookie不回退，不能把“能启动”视为持续运行兼容。
