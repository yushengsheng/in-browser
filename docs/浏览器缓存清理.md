# 所选窗口缓存清理

在主列表勾选窗口后，点击“取消选择”后面的“清理缓存”。仅处理本次选中的本地窗口；运行中、关闭尚未完成或无法确认已关闭的窗口会跳过，请正常关闭后重试。不会强制关窗。

当前清理浏览器资料目录中的以下可重建缓存：

- `Default/Cache`、`Default/Code Cache`、`Default/GPUCache`
- 根目录的 `GPUCache`、`ShaderCache`、`GrShaderCache`、`DawnGraphiteCache`

只删除这些目录内的普通缓存文件，保留目录本身。下次访问网页时，浏览器会按需重新生成缓存，首次加载可能需要重新下载资源。

Cookie、密码、网站本地存储、IndexedDB、Service Worker、网页会话及标签恢复文件、历史、偏好、配置、签名、密钥、下载、原比特来源和备份均不在清理范围。不会根据文件日期判断资料是否“过期”，也不会遍历其他位置搜索名称含 cache 的文件。此操作不删除用于维持登录和恢复标签的数据；网站自身的登录有效期仍由网站决定。

结果显示已清理、跳过、失败的窗口数量及已删除缓存文件的逻辑大小；该大小不等于系统磁盘实际回收的空间。没有可清理缓存也算已检查完成。个别文件被占用时会保留未完成部分并报告失败，已完成的计数保留，可再次执行。通信中断时不把结果未知的窗口当作成功。

## 维护边界

- `profile_cache.py`只接受明确的1至100个有效且不重复的窗口ID，身份和资料路径须与目录库及本地受管位置一致。
- 整批占用现有活动门禁，每窗使用原生命周期锁；打开、保存、删除等现有动作继续按原规则协调。界面冻结本次选择，按100项串行请求，保留选择、搜索和分页，不增加后台常驻任务。
- Windows逐级持有目录句柄，拒绝链接、Junction、重解析点及特殊文件；普通文件通过句柄核对身份后删除，防止路径检查后被替换。账号资料不参与缓存内容扫描。
- 清理前先验证该窗口全部白名单子树；有目录、数量或深度异常时停止。每窗最多100000项、4096个固定目录句柄和32层深度，时间预算每窗30秒、每批120秒；这些预算不构成底层文件操作或锁等待的硬墙钟保证。
- 不支持安全文件句柄操作的平台明确失败。当前产品支持Windows；本轮不声称已在用户那台Windows 10上实测。

验证使用合成Cookie、密码库、网页会话与网站存储标记及缓存文件，要求非缓存文件内容和身份保持；覆盖选中范围、运行/未知状态、链接越界、文件占用、部分计数、重复清理及窗口操作互斥。所有验证产物在项目`测试文件夹/`保留，用户手动删除。
