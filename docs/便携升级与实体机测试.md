# 便携升级与实体机测试

GitHub下载的是干净程序包，没有你的账号窗口。v0.2.0为便携测试版，真实账号在另一台实体电脑上的长时间登录保持仍需验证。

## 带已有资料升级

1. 在原电脑正常关闭全部浏览器窗口和管理器，保留完整旧程序目录作为备份。
2. 把新版ZIP解压到一个新的空文件夹，先不要启动。若已经启动过，请重新解压一份新目录，避免混入新生成的资料和密钥。
3. 将旧程序中的以下三个文件夹整体复制到新版的同名位置；内核目录如提示同名合并，可保留旧目录已有的内核文件。

| 旧程序目录 | 复制到新版的同名位置 | 内容 |
|---|---|---|
| `app/data` | `app/data` | 全部窗口资料、登录信息、目录密钥、设置和恢复备份 |
| `app/local-engines` | `app/local-engines` | 与原资料、签名根匹配的独立内核 |
| `app/engines` | `app/engines` | 已有的原始内核库存，保留其他已适配版本 |

请保留整个`app/data`，不要只取Cookie文件，也不要把新旧密钥拆开拼接。使用新版包自带的`runtime`，不要用旧运行环境覆盖它。

## 换实体电脑

关闭窗口和管理器后，将上面准备好的**整个新版文件夹**复制到另一台Windows 10/11 x64电脑，再双击“启动本地浏览器.cmd”。优先放在层级较浅的目录，例如磁盘根目录下的程序文件夹。

先打开序号11，核对原网页和平台登录，再测试正常关闭、重开及长时间运行。测试同一账号时，先关闭原电脑对应窗口，避免平台自身的同时在线限制干扰结果。代理应在目标电脑可用；检测失败时程序不会改为直连。

新设备仍执行原有环境检查：148允许已验证的原厂设备差异，其余内核保持严格检查。系统没有可用短路径且目录过深时，需要移动整个程序文件夹。测试中有异常请保留旧备份，不删除或重新同步覆盖原资料。

三个资料文件夹包含账号秘密，只在你自己的设备间保存，不要上传到公开仓库或发行附件。
