# 便携升级与实体机测试

含已有资料的完整便携目录同时携带程序、运行环境、内核、配置、资料及密钥；新电脑不需要已有资料或比特客户端。干净发行ZIP只带程序和运行环境，没有你的账号窗口、代理凭据或旧密钥，不能当作已有账号的便携包。已生成的0.2.2 ZIP是历史包，当前目录后续修复不会自动进入旧ZIP。真实账号在另一台实体电脑上的长时间登录保持仍需验证。

**v0.2.8便携包使用覆盖后正常启动的更新方式。** 关闭全部浏览器窗口和管理器，将完整新版包内容覆盖到原v0.2.7目录，再双击原目录的`启动本地浏览器.cmd`。新包把完整程序放在独立载荷中，由正常入口校验并自动更新原程序，资料和密钥保持原位。旧的完整迁移及手动更新脚本已停用；旧版v0.2.7 ZIP保留原样。支持来源、空间需求和中断恢复见[原地更新](原地更新.md)。

## 正常使用与换机

1. 在原电脑正常关闭全部浏览器窗口和管理器，保留原完整目录作为备份。要携带的是**已带资料、文件完整且路径可完整复制的整个便携目录**。
2. 将整个目录完整复制到新电脑或移动盘的合理短路径，建议放在盘符根目录下的短文件夹，例如`D:\LB`。包含`.program-packages`的新版完整目录必须连同该载荷目录一起复制；不要只复制`app/data`，也不要拆开资料、密钥、内核与运行环境。
3. 在另一台Windows 10/11 x64电脑上，直接双击该目录内的 **启动本地浏览器.cmd**。新电脑无需先执行迁移工具，无需另装Python、Node或WebView2；系统仍需自带.NET Framework 4.7.2或更新版本。不要在ZIP内部直接运行。

从移动盘再复制到新电脑时，同样完整复制到合理短路径后直接启动。复制提示文件过长、失败或缺件时不能选择“跳过后继续”；残缺目录不能作为成功的便携包使用。便携支持不代表可以放在任意深度的目录或使用系统本身不支持的文件格式。

## 旧长目录与复制边界

旧内核转为短布局后，原长目录仍会保留。即使原电脑能启动，保留的旧长目录也可能让资源管理器在复制阶段失败；新电脑的首次启动发生在复制之后，不能修复尚未复制成功或已经跳过的文件。此类旧目录须先在原电脑准备并校验可完整复制的整理副本，再按上面的正常步骤携带。当前不提供一键移除旧长布局的整理功能，覆盖更新也不会清理已有内核；仅缩短外层文件夹名称不一定足够。

`app/data`包含窗口资料、目录密钥、设置及恢复备份，`app/local-engines`包含与资料签名根匹配的独立内核，`app/engines`包含原始库存。升级保留它们的原位置；换机时连同整个程序目录一起复制。不要只取Cookie文件、拼接新旧密钥，或把未复制完整的目录当作成功结果。资料不会因覆盖更新上传到外部服务。

## 实体电脑验收

从完整便携目录双击启动后，已有账号资料、原签名及环境基线不会因换目录而重置。短布局减少内核目录深度，但仍需按完整资源树检查实际路径，不能保证任意深目录可启动。

先打开序号11，核对原网页和平台登录，再测试正常关闭、重开及长时间运行。测试同一账号时，先关闭原电脑对应窗口，避免平台自身的同时在线限制干扰结果。代理应在目标电脑可用；检测失败时程序不会改为直连。

新设备仍执行原有环境检查，具体兼容范围以[架构与功能](架构与功能.md)记录的已认证构建与策略为准。若复制失败或启动提示缺件，须回原电脑的完整目录处理；系统无法从被跳过的文件中还原原件。测试中有异常请保留旧备份，不删除或重新同步覆盖原资料。本机复制和合成测试不能代替第二台实体电脑的实际账号登录与长时间运行验收。

三个资料文件夹包含账号秘密，只在你自己的设备间保存，不要上传到公开仓库或发行附件。
