# 便携升级与实体机测试

含已有资料的完整便携目录同时携带程序、运行环境、内核、配置、资料及密钥；新电脑不需要已有资料或比特客户端。干净发行ZIP只带程序和运行环境，没有你的账号窗口、代理凭据或旧密钥，不能当作已有账号的便携包。已生成的0.2.2 ZIP是历史包，当前目录后续修复不会自动进入旧ZIP。真实账号在另一台实体电脑上的长时间登录保持仍需验证。

## 正常使用与换机

1. 在原电脑正常关闭全部浏览器窗口和管理器，保留原完整目录作为备份。要携带的是**已带资料、文件完整且路径可完整复制的整个便携目录**。
2. 将整个目录完整复制到新电脑或移动盘的合理短路径，建议放在盘符根目录下的短文件夹，例如`D:\LB`。不要只复制`app/data`，也不要拆开资料、密钥、内核与运行环境。
3. 在另一台Windows 10/11 x64电脑上，直接双击该目录内的 **启动本地浏览器.cmd**。新电脑无需先执行迁移工具，无需另装Python、Node或WebView2；系统仍需自带.NET Framework 4.7.2或更新版本。不要在ZIP内部直接运行。

从移动盘再复制到新电脑时，同样完整复制到合理短路径后直接启动。复制提示文件过长、失败或缺件时不能选择“跳过后继续”；残缺目录不能作为成功的便携包使用。便携支持不代表可以放在任意深度的目录或使用系统本身不支持的文件格式。

## 旧长目录与可选维护

旧内核转为短布局后，原长目录仍会保留。即使原电脑能启动，保留的旧长目录也可能让资源管理器在复制阶段失败；新电脑的首次启动发生在复制之后，不能修复尚未复制成功或已经跳过的文件。此类旧目录须先在原电脑准备并校验可完整复制的整理副本，再按上面的正常步骤携带。当前工具整树保留旧目录，尚未提供一键移除旧长布局的整理功能；仅缩短外层文件夹名称不一定足够。

**完整迁移到新目录.cmd**是原电脑上的可选维护复制工具，可用于旧程序升级或需要逐文件校验的复制，不是新电脑正常启动的必经步骤。需要使用时：

1. 选择原电脑上仍能正常打开的完整目录作为来源，正常关闭全部浏览器窗口和管理器；不要使用曾跳过文件的残缺副本。
2. 升级时将干净新版ZIP解压到短目录，只作为新版程序基础，不先启动，不覆盖原完整目录。
3. 从所选程序目录运行工具，填写完整来源和一个尚不存在的短目标目录。目标根路径最多80个Windows字符单位，工具还会按旧内核实际文件树检查；旧长布局可能要求更短目标。等待全部校验成功后再使用目标，原目录作为备份保留。

该工具完整保留以下旧目录，升级时使用所选新版公开程序及运行环境；它不会自动清除已保留的旧长目录：

| 旧程序目录 | 复制到新版的同名位置 | 内容 |
|---|---|---|
| `app/data` | `app/data` | 全部窗口资料、登录信息、目录密钥、设置和恢复备份 |
| `app/local-engines` | `app/local-engines` | 与原资料、签名根匹配的独立内核 |
| `app/engines` | `app/engines` | 已有的原始内核库存，保留其他已适配版本 |

工具会检查闭窗、来源密钥、签名、内核、目标空间和来源稳定性，使用长路径文件操作完整复制并逐项核对摘要，全部成功才发布目标。它不会改写源目录、原指纹、资料密钥或Cookie期限；中断、取消或失败只保留目标旁的未完成副本，不把它当成功。不要只取Cookie文件或拼接新旧密钥，资料不会自动上传。

## 实体电脑验收

从完整便携目录双击启动后，已有账号资料、原签名及环境基线不会因换目录而重置。短布局减少内核目录深度，但仍需按完整资源树检查实际路径，不能保证任意深目录可启动。

先打开序号11，核对原网页和平台登录，再测试正常关闭、重开及长时间运行。测试同一账号时，先关闭原电脑对应窗口，避免平台自身的同时在线限制干扰结果。代理应在目标电脑可用；检测失败时程序不会改为直连。

新设备仍执行原有环境检查：148允许已验证的原厂设备差异，其余内核保持严格检查。若复制或维护工具提示来源缺件，须回原电脑的完整目录处理；系统无法从被跳过的文件中还原原件。测试中有异常请保留旧备份，不删除或重新同步覆盖原资料。本机复制和合成测试不能代替第二台实体电脑的实际账号登录与长时间运行验收。

三个资料文件夹包含账号秘密，只在你自己的设备间保存，不要上传到公开仓库或发行附件。
