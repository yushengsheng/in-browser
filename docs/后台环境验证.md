# 后台环境验证

同步登记与正常打开前的环境校验使用后台验证。支持的现代内核采用 Chromium 新后台模式 `--headless=new`，104使用下述独立桌面。继续使用原签名、原内核和独立空profile，保留两次登记、第三次核验及46项稳定信号检查。

验证页使用`https://probe.invalid/<随机标识>`，通过Chromium CDP Fetch在请求发出前直接提供固定HTML与安全响应头，不创建HTTP监听和服务器线程。确认同会话、同主frame、精确GET文档、响应确认及页面安全上下文后，才执行原两次采样。原离线代理和DNS限制保留；失败时停止验证，不能把外部网页或错误页当成验证页，也不重建旧基线。该方式参考Chromium官方协议及Playwright的请求拦截实现，无新增依赖。

104内核早于统一headless实现，改用不切换到用户前台的独立Windows桌面，以正常渲染模式验证；仍不在用户桌面显示窗口。其他已核实版本继续使用新后台模式。所有路径保留相同指纹门禁；104把运行时日志留在测试profile，防止旧内核向不可变内核目录写`debug.log`。新内核可能提前创建地址栏WebUI，仅识别Chromium公开的两个精确内部地址，未知页面仍拒绝；空白标签启动允许在5秒内就绪。

此模式仅供内部离线空白验证调用。正常账号窗口不加后台参数，代理和正常打开方式不变。验证失败仍拒绝，不改写既有基线，也不自动改为前台重试。

若后台验证进程异常、未能正常退出，程序会停止本次操作并保留临时资料，绝不强杀。此时已无可见检查窗口可手动关闭；请保留程序目录，正常重启电脑后再试。当前不自动清除无法确认已退出的旧测试资料。

没有增加依赖。采用 Chromium 已有统一浏览器实现；124版不支持新的隐藏Target参数，因此不依赖该接口，也不采用弹出后再隐藏的方式。

## 历史验证

- 当前10个窗口（148内核）：全部46项已登记稳定信号与原基线一致；观察期间未发现测试窗口显示在桌面或占据前台。
- 124内核：独立空白兼容夹具，在未切换到用户前台的Windows隔离桌面运行正常模式，再与后台模式比较，46项一致。该夹具使用已有签名载荷，不代表重新验收已删除的旧124账号窗口。
- 所有测试浏览器正常关闭，临时资料清理完成；当前目录库全表摘要保持不变。
- 默认自检61项通过；专项工具通过时仍不能证明所有网页可见信号或跨电脑表现完全一致。

现场复核命令：

```powershell
.\runtime\python\python.exe -B tools\verify_background_probe.py --execute
```

该命令会真实启动临时后台浏览器，只使用受控验证文档，输出计数、布尔、耗时及安全字段名；不读取账号profile或输出窗口名称、地址和凭据。不加`--execute`不运行专项。Fetch替代及最新回归范围见[本轮验收报告](../analysis/launch-ten-20261113/验收报告.md)。
