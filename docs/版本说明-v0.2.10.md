# v0.2.10 版本说明

本版沿用 v0.2.8 的 Windows x64 便携包及完整覆盖更新方式，修复已复现的导入发布占用问题，并补齐失败定位信息。

## 导入可靠性

- 资料已复制完成后，Windows 短暂占用可能使资料目录或签名文件发布失败。现在仅对发布操作明确返回的错误码5/32/33尝试最多三次，间隔50/100毫秒；每次完整重验路径、绑定、文件内容与签名。
- 持续占用仍报告失败并保留恢复副本；资料变化、目标冲突和其他错误继续拒绝。保持原有5项并行、取消、去重及不覆盖来源和已有窗口的规则。
- 失败阶段、错误类别、系统错误码及公开代码位置以加密形式保留最近100条。批级错误只记一次原始原因；不保存异常文字、账号、来源路径或凭据，诊断写入失败不改变导入结果。

## 内核与升级

全部21个已支持精确内核的适配代码、创建资源、签名处理及校验规则完整随包更新；随包提供原始148内核，其余仍按需部署。

支持从官方v0.2.7、v0.2.8、v0.2.9完整覆盖升级。正常关闭全部浏览器和管理器后，将新版ZIP全部内容覆盖到原目录，再运行“启动本地浏览器.cmd”。保留整个目录及`.program-packages`，资料、密钥和已有内核仍按原更新流程保护。旧版发行包不改写。

## 验证与限制

本轮曾在合成批量中断续传中复现提交阶段 PermissionError（Windows错误码5），据此修复并加入真实文件句柄回归。

历史两批全部失败只留下“来源关键资料校验”和“复制变化”的通用提示，缺少具体失败栈；不能把本轮发布占用复现认定为那14项历史失败的唯一根因。新诊断用于保留以后故障的准确位置，未放松完整性检查来掩盖失败。

默认检查与最终针对性复测汇总143项通过、0失败、0跳过；最终随包Python3.13.17另执行8项诊断、7项真实Windows句柄发布及10项打包回归，全部通过。首次检查中新测试的句柄权限未正确产生占用，修正测试夹具后重新验证，不将这次夹具失败视为产品故障。原10000项队列后接120项完整资料中断续传的顺序连续三轮通过。

具体发行ZIP的完整清单、源码一致性和7来源首次准备桌面环境导入结果记录在GitHub该版本发布页。真实来源验收使用独立副本和离线环境探针，不打开账号网站；不能代替正式界面逐项点击、跨设备或真实账号长期登录验收，也不能承诺所有环境永不出现导入失败。
