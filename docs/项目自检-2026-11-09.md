# 项目自检记录（2026-11-09）

本轮检查生产源码、现有测试及关键失败恢复路径。源码修改前保留快照；账号资料只通过只读检查器核对，真实开窗使用独立合成窗口。

## 已修复

| 问题 | 修复与验证 |
|---|---|
| 导入暂存清理被占用打断后，归属凭据可能先被删除，导致永远无法重试 | 复用已有删除模块的受管清理，最后移除凭据；用 Windows 独占文件句柄复现及复测，通过释放占用后重试 |
| 续签或保存配置已提交，随后报错，可能误删已被目录引用的新签名文件 | 只有权威读回确认未引用才清理；不能确认时保留；覆盖提交前、提交后和读回失败 |
| 全局设置逐窗提交，失败会留下部分更新，并产生大量数据库提交 | 设置与窗口待应用标记同事务提交；失败整体回滚 |
| 迟到的列表或初始化回复覆盖新名称、分组、归档状态或已保存设置 | 列表拒收旧版本；初始化能力和同步任务仍正常恢复；设置保存独立版本保护三个读取入口，保留草稿与设置页渲染 |
| 普通浏览器控制接口已就绪，但实际窗口尚未显示就报告打开成功 | 普通启动在原有 25 秒预算内等待可见窗口；后台验证仍可无窗口；超时保留进程和资料 |
| 接管已有浏览器只比对内核、资料和端口，遗漏指纹配置路径 | 核对唯一指纹参数；缺失、重复或不同路径拒绝，兼容 Windows 大小写、短路径及目录别名 |
| 撤销下载目录时，文件替换失败却提前清除管理标记，使重试失效 | 启用时先保存归属，撤销成功后才清除；覆盖文件替换失败和末尾目录保存失败 |
| SOCKS 慢握手占住线程，使代理退出及浏览器存活检查排队 | 浏览器归属检查使用单独的一条工作线程；只在独立代理已进入退出流程后启动 6 秒进程退出兜底，覆盖握手与线程池退出阻塞，不结束浏览器 |

代理的 96 个数据连接限制和 10 秒网络检测预算保持不变。归属检查线程只随该窗口的代理进程存在；正常退出会取消兜底计时器，清理只接受当前实例的运行记录。

## 轻量与结构

- 沿用标准库、现有加密与桌面依赖，没有增加框架、构建步骤或常驻服务。
- 设置业务从 API 分派移入现有 ManagerService；同步清理复用现有归属验证，去掉重复树遍历。
- 单次本机测量，1000 条临时加密合成窗口保存设置：数据库提交从 1001 次降为 1 次，连接从 1003 次降为 2 次；耗时从 3.939 秒降为 0.8596 秒。该结果只说明这次合成测试，不代表真实同步吞吐或所有机器性能。
- 已查阅 GitHub 上 pywebview 和 proxy.py 的维护状态与 BSD-3-Clause 许可证。项目已使用 pywebview；本轮修复集中在现有事务、归属和生命周期逻辑，更换整套代理框架没有经验证的收益，因此未引入。
