# 导入提速与真实进度

日期：2026-11-11。本次仅修改单窗口导入效率与进度显示，保持串行、两步确认、不覆盖已有窗口、当前项完成后取消后续项，以及持久任务恢复规则。没有生成便携包、更新GitHub或发布版本。

## 实现

- 单项导入在受保护内核校验作用域中运行。Windows只读共享句柄阻止被缓存内核文件写入和替换；完整树、文件身份、精确构建和签名根仍核对，作用域结束即释放。部署暂存目录不缓存，已有写入者导致无法保护时走原内容读取。
- 复制继续使用标准库系统复制，单文件最多尝试3次；目录操作重试时保留已完成文件。来源前后及目标内容摘要、链接和目录清单检查均保留。成功返回刚校验的清单，消除调用方紧邻的重复读取。
- 登录资料准备、Cookie处理、三次后台环境验证、逐文件落盘、准备后清单及提交/恢复校验保留。共享的`ManagerService._manifest`没有改变语义。
- 批次百分比按已处理窗口计数，成功/跳过/失败分别显示。当前窗口单独显示阶段、实际复制/校验容量、落盘文件数、验证轮次和耗时；未知总量不显示伪造百分比。复制100%不是导入成功。
- 高频进度仅保存在当前工作线程的内存状态，通过原1秒轮询读取，不逐块写数据库。持久序号继续用于恢复，展示序号使用剩余任务位置，兼容删除历史项后继续。

## 实测性能与边界

- 同一148内核连续完整校验2次，摘要实际读取量由1,486,260,090字节降到743,130,045字节，减少50%；该样本用时1.494秒与0.849秒，仅代表这一校验环节。
- 合成复制加原本紧邻摘要的3轮交替顺序中位数：256×64KiB由1.7146秒至1.6861秒；1000×1KiB由2.6416秒至2.3313秒。单复制函数增加保护与计数有少量成本，收益来自完整调用链复用摘要，不能宣传为全程提速比例。
- 没有在用户另一台电脑上复测原先超过3分钟的导入，也没有进行真实网站登录状态验收。本次真实内核运行覆盖104和148，不等同全部21核跨设备实测。
- **104已有后台窗口问题仍未解决**：有无校验复用两组都观察到屏幕内可见Chrome验证窗口，均未抢前台；148未出现。专项整体`success`保留为`false`，不能把环境数据检查通过表述为整个专项无异常。本次未改变该显示机制。
