# 开发与自检

## 原则

先看[架构与功能](架构与功能.md)确认现有职责，再做小范围变更。稳定和资料可恢复优先；不为整理代码修改代理门禁、线程/连接数、取消语义、指纹值、清理规则或默认设置。

`app/data`、内核、随包运行环境和历史回滚资料不是源码清理对象。不要批量执行旧分析脚本，不要启动真实账号窗口或使用真实代理来验证纯函数改动。诊断只输出布尔、计数及匿名摘要，不打印异常中的地址、账号、令牌或资料路径。

## 常用命令

从项目目录运行：

```powershell
# 默认：源码静态检查、隔离Python夹具、Node界面状态测试
.\runtime\python\python.exe tools\check_project.py

# 只读：当前目录库、密钥、签名、基线、资料和随包文件
.\runtime\python\python.exe tools\inspect_installation.py

# 指定报告，便于前后比较（不改资料）
.\runtime\python\python.exe tools\inspect_installation.py --report analysis\reports\before.json
.\runtime\python\python.exe tools\inspect_installation.py --compare analysis\reports\before.json
```

`check_project.py`默认不启动浏览器、不使用用户数据和真实网络。它检查测试程序输出的`success/checks`，不会把“退出码0但内部失败”算通过；子进程超时、输出上限和脱敏失败日志单独报告。Node未安装时明确记录前端检查跳过，不把跳过算通过；产品启动本身不需要Node。

报告默认在`analysis/reports/`，可加`--report`指定目标；`check_project.py`要求报告参数为绝对路径，`inspect_installation.py`也接受相对路径。后者只向临时目录复制稳定的数据库及WAL，再连接副本；运行中、占用无法确认或读取期间变化的profile不算完整通过。非空回滚日志会保守拒绝，不清理原文件。环境基线只验证结构与绑定，不运行实时探针。

新安装报告额外记录目录库全表摘要。用新报告互相比对可覆盖外层索引字段和来源绑定；旧报告只有配置密文及闭窗资料摘要时，`comparison_coverage`会明确标记全表证据缺失，不能向过去补证。

## 按风险选择验证

覆盖更新的`test_update_guard.py`、`test_inplace_update.py`、`test_overlay_update.py`及`test_portable_bootstrap.py`纳入默认自检，覆盖清单与版本门禁、资料/内核保持、事务恢复、首次安装续跑、重复启动、旧缓存和进程占用信息缺失。发行布局与ZIP边界由`test_release_builder.py`、`test_release_archive.py`及`test_release_boundary.py`检查。用户只需完整覆盖新版包后正常启动；不再提供单独更新或迁移CLI。`analysis/inplace-update-20261112/verify.py`及其报告保留为旧事务实现的历史故障试验证据，不自动代表当前启动和包布局已通过强退专项。不把Exception回滚等同进程被直接终止，不使用真实账号；相关边界见[原地更新](原地更新.md)。

窗口排列使用`tests/test_window_layout.py`合成进程/目录夹具，已纳入默认自检，覆盖跨包拒绝、PID复用、参数边界、负坐标屏幕、部分失败、未知归属及独立设置。前端覆盖取消、迟到返回、重复操作和保存后排列。`analysis/window-layout-20261111/verify_native.py`是显式Windows桌面专项，只创建本脚本的合成原生窗口并在结束时关闭；不会读取或移动账号窗口。细节见[窗口排列](窗口排列.md)。

尺寸受限后的重复排列另验证当前 `WM_GETMINMAXINFO` 限制：仅实际尺寸与请求按系统限制调整后的结果一致、位置正确且查询前后归属和几何未变，才报告已排列并提示尺寸调整；查询失败、无响应或无匹配限制仍失败。查询每窗最多100毫秒、整批额外预算200毫秒，不保存过期尺寸限制。

本机纯回环真实浏览器专项：

```powershell
.\runtime\python\python.exe analysis\browser-proxy-boundary-regression.py
.\runtime\python\python.exe analysis\portable-copy-regression.py
```

这两条会使用用户窗口的独立副本并启动测试浏览器。运行前先检查既有进程和profile占用，确认目标窗口已正常关闭；只清理本次创建的实例，原窗口资料不参与实验。专项脚本不是默认自检的一部分。

## 扩展一个功能

1. 在现有模块选择一个明确职责。界面只收集输入，验证/业务写入放在后端。
2. 如需桥接动作，在`api.dispatch`显式加入，保持`{ok,data,error}`包装；不向界面暴露内部对象。
3. 保留`ManagerService`现有方法边界和底层兼容重导出。改变字段格式时提供显式迁移，不靠猜测或默默降级。
4. 增加能覆盖真实边界的最小验证；默认安全测试加入维护入口固定白名单，危险专项另写清楚。
5. 运行匹配风险的检查，确认原目录库和资料快照不变，更新架构功能表及必要边界。

## 文档和证据

- 当前实现以`docs/`为准；根目录使用说明面向用户。
- `tests/`放当前项目契约和界面状态回归；已有稳定的专项夹具暂保留原路径，由统一入口调用。
- `analysis/`是历史研究和证据，不是产品依赖目录；不能因没有生产import就删除迁移/恢复证据。
- 清理前保留源码快照，并写明移动/删除的理由。不能证实等价的重构暂缓，不以行数减少代替结构清晰。

## 新来源与批量同步验证

`test_engine_validation.py`覆盖同批10线程共享受保护内核句柄、原始与恢复摘要隔离、批次结束后重新读取、既有写入者回退、暂存目录不缓存，以及工作线程异常/任务提交失败后等待在执行任务退出再释放句柄。`test_engine_portability.py`另验证current内核只读校验达到10路、旧内核并发升级只发布一次及等待部署锁期间来源变化仍拒绝。真实启动验收同时统计业务线程、控制器调用及Popen返回至controller.open返回的重叠；可见窗口、CDP、平台及UA另行逐窗核对，不能把该返回区间当成精确首次就绪时刻。

批量的10路验收采用原有整段开窗/关窗操作指标，逐窗核对真实创建、可见窗口、CDP和进程身份，并执行正常关闭后二开。另行保留上述Popen至控制器返回的细分时间区间；这一峰值随启动速度变化，不要求它恰好等于10，也不能将整段操作的10路说成进程创建区间同时10路。测试不加入等待或屏障改变启动时刻。

内核部署只在Windows明确访问/共享失败时允许顶层再尝试一次：原始winerror为5/32/33，或CRT仅提供PermissionError且errno=13、无winerror。每次重新执行原完整校验，失败等待50毫秒；嵌套ensure/ensure_current合计最多两次。操作前后只核对本key目录的一层暂存名称，出现新增未清理暂存或快照未知时不重试；完整性、签名、链接或其他异常（包括被清理错误遮盖的原异常）仍拒绝。真实独占句柄覆盖恢复及持续失败，另覆盖残留不继续复制、旧暂存保留、来源变化拒绝和current并行。永久ACL拒绝可能多尝试一次，不因此获得权限或绕过校验。

`test_profile_process_scan.py`覆盖全部命令行扫描、辅助和改名进程占用、缺失元数据保留占用、匹配后独立进程身份复核，以及迭代器缓存对象被并发改写；不按名称预筛。`test_batch_parallel.py`的运行日志专项还用真实Windows读句柄拒绝DELETE，复现`os.replace`返回错误码5并验证加密日志可重试发布。5/32/33最多尝试3次，等待合计150毫秒（不含文件操作本身）；持续失败仍报错，其他磁盘/密钥错误不重试。

`test_probe_budget.cjs`通过假时钟运行生产采样helper，验证同步绘图不能提前消耗异步API预算、超时和拒绝仍失败、迟到结果不填补值、两读值保持及timer释放。设备枚举最多3000ms，UA/音频最多1000ms，每次CDP指纹采样调用的等待设置仍为5秒；每个探针仍执行两次采样，导航也有独立预算，不能把这些设置称为整个探针的硬墙钟上限。连续开关验收只在明确的`about:blank`测试页核对平台与UA，不拿临时Chrome内部页面作为账号页替代。

`fingerprint-continuity-tests.py`覆盖CDP Fetch提供固定验证文档：只允许同session、同主frame、精确随机HTTPS地址的GET Document；同requestId不重复处理，最多两个内部重发的新requestId，共用原5秒导航软预算，只发起一次Page.navigate。导航回复与fulfill确认可以交错，必须全部成功后才核对URL、complete、secure和frame/loader并进行原两次采样。协议、超时、重定向、外部文档或错误页均拒绝；`continuity_fetch_*`只保留固定诊断码，不回显原错误文本。当前实现已移除临时HTTP服务，历史HTTP断连恢复记录只对应旧实现。

兼容矩阵中的Windows、Linux与macOS指浏览器指纹。实际宿主分别按Windows 10/11客户端记录；不要求实体Linux或macOS。宿主版本由系统API读取，不能用系统指纹、模拟测试或Windows Server运行器替代对应宿主验收。

`test_direct_portable_launch.py`还覆盖同标题管理器只能前置本包、不同入口和PID复用拒绝；`test_source_preparation.py`验证两份独立便携目录均可只读发现同一本机比特来源。字体回归覆盖自动重算复用已固定列表、大列表、新建/明确不同选择仍校验及随机候选逗号字段的无损保存。完整流程的显式合成专项见`analysis/portable-contract-20261110/workflow-*`及[便携兼容与双包隔离](便携兼容与双包隔离.md)；它不纳入默认测试，也不读取真实账号资料。

`test_desktop_runner.py`纳入默认入口，只用合成OS和会话身份验证Win10/Win11标签、Server/ARM64拒绝、活动桌面及工作路径边界。`verify_desktop_runner.py`为可选GitHub自托管验收的只读环境预检，不能代替浏览器跨机实测，不属于产品启动要求。用户已决定本轮桌面跨机验收自行完成；不要因此派发无人承接的工作流或Server任务。

`analysis/window11-parity.py --execute`仅用于用户明确授权的实际序号11对照；按来源GUID核对身份、完整备份关闭资料，再分别正常开窗，只在专属新标签中提供无网络合成HTTPS指纹探针。原始账号观测仅进本机加密台账，报告只输出计数和相等性，不可纳入批量脚本执行。`--summarize`只整理已捕获证据。`parity-created-options-live.py --execute`仅创建独立合成目录，验证104/148实际首开尺寸、尺寸恢复与WebRTC模式0的代理门禁；不代表已测试真实站点WebRTC候选。

`test_import_cookies.py`还覆盖`session:true`与明确未来期限并存时的原厂解析语义及旧资料元数据迁移：当前值变化/过期/分区不符不覆盖、错钥匙拒绝、事务回滚、标记提交失败重试、旧schema无host hash及DataProtect原生认证。显式`verify-all-core-cookie-after-repair.py --execute --cores ...`只在新建的独立目录运行；`--expiry-migration`模拟旧标记后调用正式修复入口，检查全库现值/密文不变及二次不再修改。资料类专项结束、进程已确权正常退出后再清理，不能在运行中删除测试目录。

`test_window_creation.py`、`test_ssh_proxy.py`、`test_dynamic_proxy.py`和前端状态回归纳入默认入口。显式实测工具`verify_local_creation.py`、`verify_creation_options.py`和`verify_creation_ui.py`只接受含`local-creation-test.json`标记的独立程序包，不能用于真实`app/data`。分别验证全部内核创建/两次重开/删除、动态代理及环境重算时保留合成Cookie/LocalStorage、真实WebView表单提交与进度。网络仅使用本机回环夹具；报告只含布尔和计数。详见[本地窗口创建](本地窗口创建.md)。

`test_creation_audit.py`与`test_creation_runtime.py`纳入默认入口，覆盖新建GPU模式、JSON结构、移动电池队列/旧队列落盘，以及IP界面语言、证书参数的连续性门禁和旧记录绑定保护。前端另验证随机按钮只更新指纹、代理逐行保持、只读兼容值和系统DPR切换。真实噪声专项在`analysis/creation-audit-20261111/`，只有显式参数和独立标记空包才执行；不改用户十窗或生产噪声例外规则。部分API相同或原厂对照失败必须如实记录，不能以配置不同替代网页观测。

## 展示与轮询优化验证

`test_status_projection.py`和`test_signature_status.py`纳入默认自检，使用合成临时库和签名文件，覆盖缓存命中、密钥损坏/替换、外部新增修改删除、续签、文件替换/过期/时钟回拨、容量和重新读取上限，以及正式开窗校验不使用展示缓存。数据库测试保留WAL、每连接FULL、提交失败回滚和连接释放检查。前端回归覆盖150毫秒搜索防抖、中文组合输入、清空/重置、过期回调及等待期间分页和全选。

`test_status_projection.py`还使用临时Windows junction验证四个受管路径的缓存越界拒绝与恢复，并通过事件门确认慢状态解析不阻塞目录写入、下轮能看到修改。`test_signature_status.py`覆盖超过缓存容量的连续全量扫描，避免缓存反复淘汰失效。

进程快照仍读取所有进程命令行，仅延迟读取未必使用的名称、可执行路径和创建时间。`test_batch_status.py`补充改名内核、辅助进程占用、不可读和延迟读取时退出的回归；原PID复用、路径别名、接管及删除门禁测试保留。性能比较须同时记录冷扫描与psutil已有缓存时的耗时，不能把首次扫描收益宣传成持续轮询或整机CPU降幅。

`tools/verify_manager_ui.py --execute --package <独立测试目录> --report <报告>`使用真实 WebView 和公共桥接验证列表、编辑、分组、回收站、设置、加密导出及同步任务。只接受带 `local-creation-test.json` 标记的独立目录，创建合成资料；文件选择框定向到测试目录，不代表系统文件对话框实测。中断恢复使用有界合成故障，不能表述为操作系统强退验收。

`tools/verify_proxy_loopback.py --execute`仅在独立标记测试目录内创建合成窗口，以真实124/148浏览器验证认证HTTP/SOCKS5、信息页、标签恢复、既有窗口前置及失败不直连。测试副本还需包含`analysis/browser-proxy-boundary-regression.py`作为回环服务夹具；新入口只导入其中服务类，不执行该旧脚本的主流程。不得改用真实代理池或账号资料。创建阶段可能获取公开签名种子，浏览器代理验收本身使用回环服务。

`test_profile_copy.py`还验证Windows按文件名推导的执行位与句柄属性差异：可执行后缀及只读文件应正常复制，真实只读属性变化仍拒绝发布。文件身份、大小、修改时间、创建时间、其他属性和内容校验继续保留。验收必须区分“当前完整导入成功”和“已确定历史失败唯一原因”；已退出进程使用的旧模块不能凭磁盘当前代码反推。
