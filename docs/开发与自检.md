# 开发与自检

## 原则

先看[架构与功能](架构与功能.md)确认现有职责，再做小范围变更。稳定和资料可恢复优先；不为整理代码修改代理门禁、线程/连接数、取消语义、指纹值、清理规则或默认设置。

`app/data`、内核、随包运行环境和历史回滚资料不是源码清理对象。不要批量执行旧分析脚本，不要启动真实账号窗口或使用真实代理来验证纯函数改动。诊断只输出布尔、计数及匿名摘要，不打印异常中的地址、账号、令牌或资料路径。

## 常用命令

从项目目录运行：

```powershell
# 默认：源码静态检查、隔离Python夹具、Node界面状态测试
.\runtime\python\python.exe tools\check_project.py

# 只读：当前目录库、密钥、签名、基线、资料和随包文件
.\runtime\python\python.exe tools\inspect_installation.py

# 指定报告，便于前后比较（不改资料）
.\runtime\python\python.exe tools\inspect_installation.py --report analysis\reports\before.json
.\runtime\python\python.exe tools\inspect_installation.py --compare analysis\reports\before.json
```

`check_project.py`默认不启动浏览器、不使用用户数据和真实网络。它检查测试程序输出的`success/checks`，不会把“退出码0但内部失败”算通过；子进程超时、输出上限和脱敏失败日志单独报告。Node未安装时明确记录前端检查跳过，不把跳过算通过；产品启动本身不需要Node。

报告默认在`analysis/reports/`，可加`--report`指定目标；`check_project.py`要求报告参数为绝对路径，`inspect_installation.py`也接受相对路径。后者只向临时目录复制稳定的数据库及WAL，再连接副本；运行中、占用无法确认或读取期间变化的profile不算完整通过。非空回滚日志会保守拒绝，不清理原文件。环境基线只验证结构与绑定，不运行实时探针。

新安装报告额外记录目录库全表摘要。用新报告互相比对可覆盖外层索引字段和来源绑定；旧报告只有配置密文及闭窗资料摘要时，`comparison_coverage`会明确标记全表证据缺失，不能向过去补证。

## 按风险选择验证

| 改动 | 必须覆盖 |
|---|---|
| 桥接/API | 公开动作、禁用动作、错误包装、保存权限限制和批量结果 |
| 前端草稿/异步 | 放弃恢复、请求期间再编辑、抽屉切换、批量部分失败、焦点和busy状态 |
| 存储/加密/路径 | 错钥匙拒绝、损坏拒绝、原子失败、目录复制、越界和中断续跑 |
| 代理/启动 | 纯协议夹具；两版真实副本经代理、失败不直连、已有窗口接管和生命周期 |
| 便携/环境连续性 | 两版与全部已有窗口副本换目录、旧DPAPI失效、基线匹配/差异拒开、续签不绕过门禁 |
| 导入/复制 | 稳定快照、重复不覆盖、10→20追加、来源不可用、回滚、部分失败和取消 |
| 彻底删除 | 单项/批量与回收站、混合备份定点过滤、共享保留、相似ID/链接拒绝、占用和中断恢复、pending禁用及迟到响应 |

本机纯回环真实浏览器专项：

```powershell
.\runtime\python\python.exe analysis\browser-proxy-boundary-regression.py
.\runtime\python\python.exe analysis\portable-copy-regression.py
```

这两条会使用用户窗口的独立副本并启动测试浏览器。运行前先检查既有进程和profile占用，确认目标窗口已正常关闭；只清理本次创建的实例，原窗口资料不参与实验。专项脚本不是默认自检的一部分。

## 扩展一个功能

1. 在现有模块选择一个明确职责。界面只收集输入，验证/业务写入放在后端。
2. 如需桥接动作，在`api.dispatch`显式加入，保持`{ok,data,error}`包装；不向界面暴露内部对象。
3. 保留`ManagerService`现有方法边界和底层兼容重导出。改变字段格式时提供显式迁移，不靠猜测或默默降级。
4. 增加能覆盖真实边界的最小验证；默认安全测试加入维护入口固定白名单，危险专项另写清楚。
5. 运行匹配风险的检查，确认原目录库和资料快照不变，更新架构功能表及必要边界。

## 文档和证据

- 当前实现以`docs/`为准；根目录使用说明面向用户。
- `tests/`放当前项目契约和界面状态回归；已有稳定的专项夹具暂保留原路径，由统一入口调用。
- `analysis/`是历史研究和证据，不是产品依赖目录；不能因没有生产import就删除迁移/恢复证据。
- 清理前保留源码快照，并写明移动/删除的理由。不能证实等价的重构暂缓，不以行数减少代替结构清晰。

## 新来源与批量同步验证

新增`tests/test_source_preparation.py`、`test_sync_reliability.py`和`test_batch_status.py`均已纳入默认入口。覆盖来源变化后的重新准备、缓存行错配拒绝、9999+1批次、提交结果不确定、五个强退阶段、日志所有权/目录junction和万条状态的单次进程扫描/集中保存。前端纯VM覆盖9999上限、恢复/取消及迟到bootstrap。

首次未知来源准备允许仅对本机GUID使用正常登录会话联网；普通开窗保持独立。测试仅使用模拟API和合成资料，不得把真实会话放入fixture或输出。`analysis/import-new-source-validation.py --execute`是本次3个真实新来源的显式现场入口，不属于默认套件，不能批量运行。结果与边界见[导入与同步验证](导入与同步验证.md)。

## 彻底删除验证

`tests/test_profile_delete.py`与`tests/test_delete_integration.py`使用临时目录和合成加密资料，已纳入默认维护入口；不在真实`app/data`中创建或删除窗口。前端VM覆盖主列表、回收站、确认期间变化、分段部分失败、pending及旧响应。实现范围和恢复机制见[窗口彻底删除](窗口彻底删除.md)。

## 后台环境验证

`test_background_probe.py`覆盖后台模式仅限离线空白验证、签名和文件门禁保留、无可见窗口时就绪及正常开窗参数兼容，已纳入默认入口。`tools/verify_background_probe.py --execute`是独立的真实内核专项，读取当前目录库的临时副本，每个窗口只在系统临时目录创建空profile；不打开账号资料、不更新基线。它采样桌面窗口/前台归属，并比对全部已登记稳定信号和目录库全表摘要。未正常关闭时保留测试资料，不强杀进程。详见[后台环境验证](后台环境验证.md)。

## 全部内核验证

`core_specs.py`是21个已核实原厂构建的精确规格，不能自动探测后直接信任未知文件。`test_core_compatibility.py`与`test_legacy_sources.py`已加入默认白名单，覆盖旧保护模式、签名与来源缓存、公开种子验签和原子映射。`tools/validate_all_cores.py`仅为显式现场专项：先加密登记原有来源ID，再创建本次测试窗口；本地导入和删除只在独立sandbox目录执行，禁止用真实目录库验收。cleanup只接受登记的来源身份和精确目录，保留验证报告。此工具不属于默认自检，不可自动批量运行。

## 代理与IP页验证

`test_ip_info_page.py`和`test_proxy_runtime_stability.py`已加入默认入口，只用合成记录及回环服务。在线专项使用用户指定的加密测试代理池：`tools/verify_test_proxies.py --execute`验证实际worker转发，`tools/verify_proxy_ip_page.py --execute`验证独立空白浏览器中的信息页与标签恢复。参数不得写入脚本、命令行或报告；不再默认使用已有账号窗口的代理做联网测试。测试池有有效期，缺失、损坏或过期时明确失败。细节见[代理与IP信息页](代理与IP信息页.md)。
