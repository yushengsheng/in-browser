# 便携兼容与双包隔离

兼容能力属于程序本身，不依赖某一份指定的用户目录。正常流程是：解压干净程序包，在包内新建窗口或同步本机比特资料，正常关闭后复制整个目录，在支持的另一台Windows电脑直接双击包内启动。新电脑无需原来源资料、比特客户端，或另装Python、Node、WebView2。

## 两份程序并排使用

例如`D:\浏览器\A`和`D:\浏览器\B`各包含完整的`app`与`runtime`。每份程序只管理自己的资料、目录库、密钥、内核和运行状态；即使B由A复制、已有窗口ID和目录密钥相同，也按完整目录与进程身份区分。重复打开B只复用B的管理器，关闭A不关闭B的窗口。

两份程序均保留本机比特资料的定位和同步功能。用户分别选择同步后，来源资料被完整复制到各自包内；一份程序已经同步，不代表另一份也已同步。日常打开使用各自独立副本，不直接运行比特来源profile。完整程序目录内的两份文件树不能合并覆盖成一个目录。

同步采用“检测数量→选择窗口→开始同步”三步界面操作。打开检测页不会自动复制；每次重新检测会读取当前电脑的比特资料位置。新电脑没有比特资料时，可继续使用包内已有窗口和已具备内核的新建功能；安装并登录比特后再次检测即可，不需要重启管理器。

## 本次修正与回归要求

- 管理器复用按当前包的Python、入口脚本及进程创建时间核对，解决多个同标题管理器误前置。
- 自动按IP或噪声重算保留原已固定的字体过滤配置及资料保护密钥。新建或明确不同的字体选择继续执行既有校验。
- 随机字体候选必须能按已有逗号字段无损保存，并符合原环境检查的完整字体探测预算，避免名称或数量导致新建随机失败；不扩大环境放行范围。
- 回归必须同时保留同步后的持久及会话Cookie、LocalStorage、SessionStorage、IndexedDB、标签和导航；不延长Cookie期限，不用空密钥替换原密钥，不扩大原设备差异放行范围。

独立合成验收从实际0.2.3 ZIP开始，经过真实新建、同步复制与提交；A/B克隆同时运行同ID窗口，写入不同本地存储后互不覆盖，关闭A时B继续运行。随后将原路径及合成来源改名使其不可用，在副本中模拟旧用户DPAPI不可解，禁止短路径别名及来源API调用，两份记录各两轮正式重开，五类存储、标签、导航、规范指纹、46项基线和同钥绑定保留。来源API和资料为合成夹具，不冒充真实比特云端或平台账号验收。

## 边界

目标为Windows 10/11 x64及系统自带.NET Framework 4.7.2或更新版本，目录需要可写。短布局及完整资源树检查减少对系统长路径设置和8.3别名的依赖，仍应使用合理短的根目录；不支持任意深度。历史长目录和曾跳过文件的残缺副本不能靠新电脑首次启动补齐。

用户明确指定的包外下载目录、网络路径等外部资源有其自身可达性要求，不会自动搬运包外文件或改写其用途。仅登记在Secure Preferences的外部扩展及其保护校验尚未完成真实内核验收；本次不会盲改保护结构，也不将其列为已覆盖。

同机多进程和模拟旧用户不可解不能代替真实第二台实体电脑、移动盘或平台账号长时间登录测试。代理需在目标电脑可用，平台过期或撤销的登录凭证不能由便携复制恢复。
