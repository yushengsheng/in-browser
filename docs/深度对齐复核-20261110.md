## 一、从比特导入后跨设备保留页面与登录

### 两条恢复链路

原厂主程序在打开前按各项同步开关分别恢复历史、IndexedDB、LocalStorage、书签、密码及扩展资料；Cookie经单独快照接口处理。标签使用URL集合，部分较新构建另用`~TabGroups`。关闭收尾再按开关上传，传输格式也不同于本地的完整目录复制。

本地“同步窗口”发现本机已有的完整比特资料，在关闭状态创建完整独立副本，再补齐配置中的启动Cookie快照、认证资料密钥并建立环境基线。相同来源已有本地绑定时跳过，来源后来的变化不覆盖本地。此后本地窗口自己的关闭、重开和换目录沿用原生资料；换电脑需要复制最新的**完整程序目录及配套资料、目录密钥、签名根和匹配内核**。仅导出的加密配置不是完整资料备份。

| 项目 | 原厂所选恢复链路 | 本地当前行为与结论 |
|---|---|---|
| 数据时点 | 取决于云端最近成功上传及启用的分类 | 取决于导入时的本机完整快照；之后各自独立。同步后继续使用原厂，不能期待旧本地副本自动得到新状态 |
| 标签与页面 | URL集合及条件启用的TabGroupStore | 原生Sessions、导航栈和Session Storage随整树复制；机制不同，不能仅凭同一网址认定全部网页内存相同 |
| Cookie | `Dp/Ip`采样、转换、上传，启动前`Qf/Vt/$f/ep`回放 | 保留原生库，并在首次导入补启动快照；不反复重放旧快照 |
| Cookie分区和期限 | 所选快照出口会移除分区字段并设置一年期限；并非直接统一修改原生数据库 | 保留分区，过期项不续期。不会为模仿快照而改变存储隔离或凭证期限；延长本地期限也不能延长服务端授权 |
| LocalStorage/IndexedDB | 按开关分类下载 | 整个profile携带；还需原DataProtect保护块及同一资料钥匙 |
| SessionStorage | 所选`ip/cp`链路未见整库同步；不代表整个产品绝对不存在其他路径 | 随资料树和原生标签会话保留。不是所有正在运行的JS内存都能保存 |
| 已存密码 | 原厂密码同步有独立格式与配置路径 | 认证并保留Login Data；迁移只重新包装同一OSCrypt钥匙，不重写密码库 |
| 扩展 | 云端分类资料及客户端助手 | 本地完整资料及路径重定位，原厂云助手禁用；外部扩展缺失或代理权限冲突会拒绝，存在实际行为差别 |
| 跨Windows用户 | 原厂客户端负责恢复其格式 | 原DPAPI包装不能通用；本地目录库保留原主钥匙，在新用户重新包装Local State；v20/App-Bound拒绝 |
| 不同物理环境 | 原厂自身也可能出现显示、字体、GPU等设备差异 | 148允许9项经原厂对照确认的有限变化；其他20个已支持构建仍严格，换机可能拒开，尚未达到所有内核同等可用 |
| 真实账号有效性 | 仍依赖实际平台及会话 | 需要自然服务器身份认证。文件、Cookie数量或页面外观都不能替代账号验证 |

Cookie精确条件：`Dp`仅处理API采样缓存，必要时从已打开且未脱离的浏览器取样，不直接写Cookie库；`cp`仅在`syncCookies`开启时上传。启动解析的`Vt/Wt`又有独立期限规则。详细原函数、原始字节偏移和可读源行号见`analysis/reports/deep-rea-vendor-findings.{md,json}`。

### 能确认和仍不能确认

历史Windows 2022/2025的148专用合成资料已通过正式门禁和五类存储两轮冷启动；这是项目既有记录，本次没有重跑这些远端工作流。真实新Windows样本曾因网络资源失败而未发出所需自然身份请求，保持计时0秒；不能称为真实登录已通过，也不能据此认定同步已丢失登录。

本次另行执行全新密钥的148同机换目录专项，验证结果记录在下方“本次验证”。**同机换目录不等于第二台Windows，也不等于完整比特客户端云同步。** 因而第一项目前可以确认资料迁移机制及受测存储连续性，不能认定所有真实网站、所有内核与原厂云端打开完全一致。

本次把原厂字段规范的73项逐项对应到当前白名单、原厂转换函数、运行参数和测试边界。原厂61个默认指纹字段全部被本地接收；本地白名单共71项。另两项为`randomPlatformVersion`及高级`extendOptions`：新建表单不直接接受，本地分别用自己的生成策略和受控保护块；这不表示导入的原生载荷或现有DataProtect丢失。接收一个字段也不等于其所有模式已在网页中生效。

机器可读矩阵：`analysis/reports/deep-rea-fingerprint-fields.json`，含73字段及5类衍生表面。当前参数库有54个预设（PC48、Android3、iOS3）、56项语言、18组WebGL参数及21个精确构建；它不是原厂完整在线随机服务。

特别核实“忽略HTTPS错误”：原厂主程序传的是旧`ignoreHTTPSErrors`参数，但当前原包Puppeteer 23.11.1的BrowserLauncher只读取`acceptInsecureCerts`，CDP Browser也由后者控制Security设置。所查四个依赖文件没有旧参数兼容。因此不能只见原厂传参就认定其已生效、本地缺一个开关；网页证书行为尚需专门实测，本次未为此新增放宽证书检查。

跨设备Canvas、GPU、字体、媒体设备等，原厂本身也不保证与旧电脑逐值一致。把所有硬件输出强行固定会改变原厂行为，不能用重写旧基线或忽略差异制造“完全对齐”。

## 本次修复

1. **随机字体在批量创建及重试时不稳定。** 原先同指纹的两份排队配置相同，但真正编译时各抽一份字体。现于登记时固定并加密保存：同指纹一次，独立模式逐项一次；失败重试沿用选择。旧队列首次执行前先持久化；因旧队列未存原始批量模式，只能逐项固定，不能还原其从未保存的共同选择。已有窗口、导入和显式字体不重抽。
2. **旧位置Cookie库漏掉同钥认证。** 增加`Default/Cookies`，与`Default/Network/Cookies`同时存在时分别认证。错钥、损坏、未知密文及超预算在Local State写入前拒绝；不回写Cookie库。它防止错配资料误判可迁移，不是已确认的真实账号掉登录原因。

修改前源码保存在`analysis/reports/deep-rea-fingerprint-before/`和`deep-rea-state-before/`。没有清理用户资料、覆盖原窗口或调整代理/并发/取消策略。
