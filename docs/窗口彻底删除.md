# 窗口彻底删除

主列表的“删除”紧挨“移至回收站”，行菜单和回收站均提供单项删除；两个列表都支持批量。归档仍然可恢复，彻底删除需要单独确认，默认焦点为取消。

## 清理范围

- 所选窗口的整个受管profile，包括Cookie、密码、历史、书签、缓存、站点存储、会话和扩展资料。
- 窗口专属扩展、全部可识别签名版本、代理状态及临时请求文件。
- 当前及历史目录库中的窗口记录、来源绑定、相关同步项和已认证导入恢复记录。
- 来源准备缓存、旧来源归档、历史settings/runtime及固定旧bootstrap中对应的项目。
- 窗口专属升级备份、可识别匿名签名和认证同步暂存副本；混合备份只过滤所选窗口，保留其他窗口。

保留原比特来源、手动导出、外部下载与备份、其他窗口以及共用内核、密钥和共享资源。程序不扫描全盘寻找副本；来源仍存在时，后续同步可以重新导入。普通文件删除无法保证抹除SSD底层、系统快照或第三方备份中的取证痕迹。

## 关闭、恢复与数据保护

删除使用现有正常关闭流程，只关闭所选受管窗口，不强杀进程。运行状态无法确认、文件占用、身份不一致、越界、链接或未知备份格式时停止并明确报错。

首个清理动作前保存认证加密计划。删除与来源同步共用现有worker互斥；每批最多100个唯一ID，界面按100个顺序提交，不增加并发。删除未完成时，所选记录禁止打开、修改、激活、归档和恢复，新同步/继续同步也会拒绝，防止旧恢复日志复活资料。

程序启动自动重试未完成计划；记录尚在时也可再次点击删除。部分文件已清理后失败，不声称原资料完整保留。只有受管副本、记录及数据库存储整理全部完成后才回执成功；计划完成即移除，不保留逐窗删除日志或永久拒绝导入名单。

无法认证的历史文件或恢复计划会保守停止，不能自动忽略。若强退恰好发生在首次写计划的中间，留下半写临时副本，也会停止并要求保留目录后人工确认；不能承诺所有磁盘故障都能靠重启自动处理。

SQLite清理启用secure_delete，提交后执行checkpoint、VACUUM并确认WAL截断。清理失败保留计划，不能把仅删除列表记录当成彻底成功。

## 验证方式

临时合成夹具覆盖加密目录库、非标准备份库名、匿名签名、混合缓存、回收站、相似ID、共享数据、junction、伪造计划、文件权限、强退、数据库占用、批量单轮整理和启动恢复。API/管理器集成及前端状态另有独立夹具。真实安装仅作只读前后比对，不以用户现有窗口试删。

本轮后端30项、集成11项、前端78项通过。另把当前安装的69份配置/签名/历史备份元数据复制到临时目录，11个窗口逐一完成删除规划，并完成单项及批量删除验收；单项删除后保留其他窗口的合成资料。此项未复制真实浏览器profile，不能代替真实浏览器进程关闭验收；实际安装的11份资料与目录库全表摘要已通过只读前后比对。
