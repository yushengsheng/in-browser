# 代理与IP信息页

## 当前行为

- 指定代理的新窗口先启动独立转发worker，再通过浏览器实际会用的回环入口检查出口；前后均确认worker归属和控制状态。失败拒绝启动，不尝试直连。
- 出口网络检测整轮10秒，包含所有备用检测源；worker准备、浏览器启动和环境检查另有原有预算。保留每窗96连接上限、TLS上游证书验证、SOCKS5远端DNS及认证隔离。
- 双向隧道共享最近活动时间。持续上传或下载不会被另一静默方向误断开；整条隧道完全空闲600秒仍回收，写入超时仍为30秒。
- 每次真实新开默认显示`https://ifconfig.co/`，本地新建窗口可明确关闭此项。先通过浏览器级接口创建并确认新的专用信息页，再替换本轮初始快照中首个网址精确匹配的旧信息页，最后前置新页；原账号标签、其他已有信息页及并发新开的页面保留。已有窗口再次打开只前置，不添加网页。
- 新信息页地址提交及旧页关闭可能异步完成；仅对同一新目标的暂时缺失或空白状态、已接受关闭的旧目标做有界状态确认。创建后的确认、旧页收尾和前置共用不超过5秒且不超过现有连接超时的固定预算，各调用使用剩余时间；不重复创建或关闭，不等待外部HTTP加载成功。旧页关闭前再次核实仍是精确信息网址，已转为其他网站或已消失时不关闭；确认失败明确报告并保留现有窗口。
- 信息页通过浏览器本身访问，无本地信息页服务器、额外扩展、脚本注入或常驻查询任务。未改原生指纹、签名载荷、资料加密和同步逻辑。
- 外部信息站的加载不作为代理门禁；某站暂时不可用时浏览器仍保留。CDP无法创建/显示标签时提示“浏览器已打开，但IP信息页未能打开”，不会为信息页失败关闭账号窗口。

## 开源方案评估

2026-11-08检查公开仓库功能、维护和许可证，并实际访问候选服务。

| 项目 | 许可证 | 采用方式或评估 |
|---|---|---|
| [mpolden/echoip](https://github.com/mpolden/echoip) | BSD-3-Clause | 使用官方部署[ifconfig.co](https://ifconfig.co/)，显示IP、地区和ASN，无须内置整站 |
| [rdegges/ipify-api](https://github.com/rdegges/ipify-api) | MIT | 沿用成熟公共出口API；api64和IPv4端点优先，再以echoip、ipinfo备用，仍共用10秒 |
| [abhinavsingh/proxy.py](https://github.com/abhinavsingh/proxy.py) | BSD-3-Clause | 完整代理框架；当前需求已有隔离转发，整体替换会增加行为迁移及生命周期验证成本 |
| [qwj/python-proxy](https://github.com/qwj/python-proxy) | MIT | asyncio多协议方案；本项目继续使用已有asyncio与PySocks实现，修复已证实的问题 |
| [ginuerzh/gost](https://github.com/ginuerzh/gost) | MIT | 适合独立代理服务；本场景引入额外二进制及维护成本无明确收益 |
| [jason5ng32/MyIP](https://github.com/jason5ng32/MyIP) | AGPL-3.0 | 功能完整，但自建需要Node、构建和服务/数据维护，超出轻量本地管理器需要 |

未复制以上仓库源码，没有新增依赖。使用成熟托管服务减少本地维护，不代表第三方站点或代理供应商永远可用。

## 测试与凭据

`test_ip_info_page.py`覆盖先新确认后旧替换、仅替换首个精确匹配页、保护其他标签、异步状态确认与固定期限、门禁及失败行为；`test_proxy_runtime_stability.py`覆盖持续上传/下载、空闲/取消回收和断线重连。均为隔离回环测试，已加入默认自检。

今后在线测试使用用户指定的7个编号代理，参数仅加密保存在本机，报告不写地址、账号、密码或出口IP；不会改动现有账号窗口的代理。测试凭据有有效期，过期后须更新。2026-11-08，7个代理的HTTP/SOCKS5两种方式，两轮各14次真实转发检测全部通过，单次约1.6～5.4秒，临时worker和文件已清理。

专项入口（均需显式`--execute`，不在默认自检中联网）：

```powershell
.\runtime\python\python.exe -B tools\verify_test_proxies.py --execute
.\runtime\python\python.exe -B tools\verify_proxy_ip_page.py --execute
```

第二条使用独立空白资料及现有签名配置，短暂显示测试窗口，验证HTTP/SOCKS5链路、信息页与标签恢复，再通过指定测试代理访问官方信息站。不会复制或打开已有账号资料。验收结果写`analysis/reports/proxy-ip-browser.json`，仅包含布尔、计数和安全错误类型；真实浏览器范围以报告中的内核为准。

2026-11-08实际验收：148内核的20项检查全部通过，包括两种代理的信息页、原标签恢复、重复前置、失败拒开及正常退出；真实echoip网页加载成功，网页出口与同worker的出口检测一致。原生载荷及签名文件未变，所有测试浏览器、worker和临时文件已清理。本轮没有重新对21个内核逐个展示该信息站，之前21个内核的指纹/资料验收见[全部内核适配验证](全部内核适配验证.md)。

只读安装比对确认原10份资料及三张资料业务表（窗口、设置、来源绑定）的索引和密文均未变，1439个随包运行文件校验通过；同步任务状态表不在该摘要比对范围。未在真实账号资料上做实验。

原有窗口的代理不是本次测试池：此前只读检查发现序号4、9的上游认证失败，序号10连通。没有自动替换它们的凭据。
