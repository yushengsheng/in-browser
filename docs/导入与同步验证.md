# 新窗口导入与批量同步验证

日期：2026-11-08。当前11个本地窗口，其中本次新增3个真实来源。单次上限9999，来源总数不截断。现有窗口编辑、10秒代理检测、独立启动和可恢复回收站规则保持。

## 实现与对应关系

1. 只发现本机资料目录中的规范化GUID，不扫描云端窗口列表；预览一次读取来源绑定集合并只枚举一次进程。
2. 新窗口首次缺配置时，使用当前正常登录会话读取该GUID的完整配置，核对ID、browserId、内核和DataProtect。按来源最后保存的出口冻结派生环境，转换器拒绝随机生成新指纹。
3. 每来源配置加密保存于独立SQLite缓存。准备时记录关键文件身份、时间、大小与内容摘要；准备前后或稍后重试时变化会重新准备或拒绝，不能旧配置搭新资料。旧大归档兼容读取并缓存，不逐窗口整包反复解密。
4. 来源GUID派生稳定键，与本地UUID一一绑定。名称、序号重复不会合并不同来源；来源删除、改名和重复同步不覆盖已有独立副本。
5. 复制完整资料并校验清单；发布前认证原OSCrypt同钥，登记两次冷启动环境基线并第三次验证。只启动空profile与本机测试页面，不访问真实账号站点。
6. 从第一次暂存写入起就认证目标、任务和work所有权，目录链在写入及发布前检查。准备记录和副本摘要先持久化，再无覆盖发布；窗口、唯一绑定和成功计数同事务提交。
7. 提交回执丢失时先读回权威绑定，不能误删可能已提交的资料；清理异常单独计warning。伪造、篡改、重放、旧未认证日志或未知目录均保留拒绝，不当作垃圾删除。

## 任务、取消与规模

- 单任务逐窗串行，单批最多9999。10000个来源仍完整预览，默认选前9999并明确剩余1个下一批，不拆成并行后台任务。
- 任务与选择保存在SQLite；重启显示interrupted，可继续未完成项。取消只停止后续项，当前项完成或明确失败；已提交项不会重复计数。
- 进度只返回尾100项、总计和items_total；取消检查不复制全部历史结果。状态查询索引和32项日志恢复块控制单次工作量。
- 列表状态一次建立进程索引，前端用ID Map合并。万条陈旧运行记录的遗忘集中持久化一次；单窗口真实打开、前置、关闭的身份/代理门禁不放宽。
- start/resume/cancel请求开始和结束均推进代次，旧进度、旧错误或待确认期间发起的旧bootstrap不能回退已确认状态；轮询保持单请求。

## 开源评估与依赖

检索了BitBrowser官方API、公开SDK包装，以及[LiteQueue](https://github.com/litements/litequeue)（MIT）、[DiskCache](https://github.com/grantjenks/python-diskcache)（Apache-2.0）等SQLite方案。它们可提供队列或API包装，但不能直接完成本项目的加密资料、文件发布、来源唯一绑定同事务提交；另装队列会引入第二套存储和重复的一致性边界。

本轮沿用项目现有SQLite/WAL/FULL事务、复制校验、加密、签名和连续性组件，仅补充持久任务与发布日志；没有引入新框架、服务或并行导入。原有配置转换器依赖Node，现将本机已验证的Node v24.11.0及官方LICENSE随包，避免只靠系统PATH。增加90,016,206字节（约85.85MiB），纳入运行环境哈希清单；仅配置转换时启动，不是常驻进程。

## 验证边界

真实资料测试为本次3个新来源及当前11份副本；10000规模使用合成记录，不等于真实9999个大资料目录的速度实测。首次逐窗配置、资料复制和基线登记存在耗时，优先保证完整性；不承诺固定每秒窗口数。

首次缺配置需联网及正常有效会话；缺失的保护配置不能从网页历史猜出。来源须完整落盘且关闭，Firefox、未知内核及v20/App-Bound仍不在支持范围。真实第二台电脑和平台风控未由本机模拟替代；五阶段进程强退测试不等于所有硬件/文件系统的断电保证。
