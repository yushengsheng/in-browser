# 已打开窗口排列

“重置筛选”后新增“排列”和“排列设置”。排列针对本包全部已打开的浏览器窗口，不受列表筛选、分页或勾选限制；同一资料打开多个普通浏览器窗口时分别排列。没有已打开窗口时只提示，不启动浏览器。

- 自适应：默认方式，按数量自动分行铺入所选显示器工作区。
- 宫格：设置起点、宽高、每行数量及横纵间距；按请求尺寸无法容纳全部窗口时，在移动前提示修改参数。
- 对角线：按横纵偏移错开，超出可用空间时从起点循环。
- 支持序号正序/倒序、主屏自动跟随或固定显示器；固定显示器断开时提示并回退主屏，不自动覆盖原设置。起点相对屏幕工作区左上角，避开任务栏。

保存只写本包加密目录库的独立`window_layout`设置，不调用原通用设置保存流程，不标记账号资料待更新。取消不保存；“保存并排列”先确认保存成功再排列。最小化/最大化窗口恢复后排列；不主动抢焦点或改变窗口前后顺序。浏览器自身可能限制最小尺寸，实际尺寸与请求明显不同时明确提示；高缩放产生的一像素舍入视为正常。

## 实现边界

通过已有`ProfileProcessSnapshot`一次枚举进程，核实当前包的资料/指纹路径、内核可执行路径、主进程参数及进程创建时间，再枚举可见的普通Chromium顶层窗口。每次移动和结果确认都重新核实归属；归属不明、进程退出或句柄变化时跳过，无法读取进程信息时明确提示。排除其他包、比特客户端、管理器、隐藏/工具/有归属的弹窗和其他虚拟桌面上的隐藏窗口。

仅新增三个API动作及两个模块，不调用同步、Cookie准备、新建、指纹生成或浏览器生命周期动作。仅向Windows发送位置和大小操作，不修改资料文件、保存的指纹配置、启动参数或站点登录数据；网页可视区域会像手动调整窗口大小一样随之变化。

使用`ctypes`调用Windows系统接口，不增加Python包、后台服务或前端构建。DPI处理仅限调用线程，结束时恢复。异步移动有界等待，并以实际窗口位置确认结果；其他操作正忙时提示稍后重试。

## 轻量开源参考

2026-11-11查阅了[PyGetWindow](https://github.com/asweigart/PyGetWindow)（BSD-3-Clause，Python/ctypes，最近推送2024-07-02）和[CMDOW](https://github.com/ritchielawrence/cmdow)（MIT，原生Win32命令行，最近推送2020-10-01）。两者都有成熟的窗口移动/尺寸接口，但不包含本项目所需的包目录归属与排列规则。参考其使用原生窗口枚举和`SetWindowPos`的方式独立实现，未复制其代码或引入整个依赖。
