# 发版与跨设备验收

## 公开内容边界

源码按`tools/build_release.py`白名单导出，包含程序、公开静态适配资源、维护工具及合成测试。不导出`app/data`、已绑定的内核、原有快捷方式、代理池、运行日志、历史报告及回滚目录。

干净Windows发行包另带随包运行环境和原始148内核。其它已支持内核随对应来源导入时部署；迁移已经导入的窗口时须复制完整原程序目录，不能用空发行包代替资料备份。目录密钥及签名根由首次启动生成，不与其他使用者共用。

初始化仅允许不存在或完全空的数据目录。中断、部分状态或密钥缺失时拒绝重建，保留已有资料。旧安装继续使用原有密钥及迁移规则。首次空管理器不访问比特登录或数据库；新来源准备依旧可能需要原厂正常有效会话。

## 发布门禁

1. 原安装只读检查并保留前后摘要；运行完整默认测试。
2. 依赖版本固定于`requirements.txt`，候选环境单独更新并查询OSV公告；不修改正在使用的随包环境。
3. 对导出源码执行gitleaks和已知本机秘密比对。压缩包附逐文件SHA256清单；源码及包中不含真实账号资料。
4. 运行`tools/verify_clean_start.py --execute`，在无原厂数据库的临时目录初始化，实际显示空管理器并正常退出。
5. 本机创建专用测试窗口，使用全新测试签名根和目录密钥，只保留测试Cookie及localhost网页存储。在原电脑登记46项基线，关闭后传输专用样本。
6. GitHub Actions在Windows 2022及2025新虚拟机中校验样本压缩包摘要、运行源码测试、干净UI验收及`tools/verify_portable_fixture.py --execute`。要求原电脑DPAPI包装不可解、同钥重新包装后可用、两轮Cookie/存储/指纹检查通过、原基线保持且正常退出。测试包使用7-Zip无损压缩，保留全部运行文件，由运行器自带7-Zip解压。
7. 必需检查有失败时保留报告，不发布稳定版；不删掉差异字段、不重登记目标机基线，也不关闭连续性门禁制造通过。

CI解压已固定摘要的样本后，仅用当前提交中追踪的公开`app/`和`tools/`文件更新测试代码；资料、内核与运行环境保持样本原件。这使每次验收对应准确的源码提交，而无需重新上传几百MB的运行环境。禁止覆盖样本资料、内核目录或历史界面输出目录。

样本和草稿仅用于候选验收。其密钥只对应公开测试资料，没有实际账号用途。原有用户资料和生产密钥始终留在本机。

## 能证明与不能证明的范围

不同GitHub运行器是独立Windows用户和新系统环境，可实测跨设备目录解密、启动和指定资料保留。虚拟机的显示、字体、音频与GPU环境也可能与原电脑不同；连续性检查只允许当前内核已完成原厂对照的差异，其他变化仍拒绝。一次通过不等于任何硬件、所有内核或平台风控永久一致。最终版本说明必须给出实际运行记录与验证范围。

原安装的只读比对涵盖窗口、设置和来源绑定三张资料业务表以及闭窗profile文件；不把这一摘要称为全部同步任务表验收。

## 保留旧指纹与登录资料

当前策略已按用户明确选择改为原厂同等表现兼容：保留原生配置、原基线和登录资料。严格登记仍为默认`verify_continuity`行为；仅正式管理器开窗显式启用`allow_device_variance=True`。独立148内核允许原厂对照实测的Canvas几何/文字、字体度量、媒体设备数量、屏幕动画偏好及WebGL1/2扩展/像素共9项稳定差异；检查数据类型、字体名称/结构、扩展格式，屏幕其他媒体查询必须相等。缺项、不稳定、未知字段变化或绑定变化一律拒绝，其他内核保持严格。正常情况使用原始启动参数，既不强制换渲染器，也不重写旧基线或Cookie有效期。

`tools/verify_login_storage.py`使用唯一专用合成窗口，检查长期Cookie、会话Cookie、LocalStorage、原标签恢复的SessionStorage及IndexedDB。默认/`--verify`模式经正式管理器门禁完成两次正常关闭和冷启动，并记录两次策略及允许的差异名称；`--storage-only-diagnostic`只验证合成资料搬迁，不接受设备兼容。CI使用正式`--verify`，不能拿诊断模式代替开窗验收。

合成登录样本仅含独立测试资料，通过单独固定摘要的小压缩包覆盖云端专用样本的资料目录。测试要求源Windows用户的DPAPI包装在新用户下不可解，同一原主密钥经新用户包装后可用，五类存储两轮全部保留，原生配置、签名及基线均未改变。默认不上传真实账号资料和生产密钥；用户明确指定真实窗口进行远端验收时，按下述独立加密流程执行。

## 明确授权的真实会话验收

`private-session-acceptance.yml`只接受手动触发，不接收PR或推送事件。独立副本仅携带授权的一个窗口，全新目录密钥和签名根，完整保留原生载荷、原46项稳定基线、原浏览器加密主密钥及资料。新信任根仅更新内核认证绑定，不重采网页基线。传输包使用一次性AES-256-GCM密钥，密文放未公开草稿附件，密钥仅通过Actions secret注入认证解包步骤；生产目录主密钥和签名私钥始终留在原电脑。

解包器先核对完整摘要、认证GCM标签，再校验ZIP成员路径和资源上限。明文临时ZIP立即清理。正式验收直接调用`ManagerService.open`，不使用离线诊断、mock或放宽基线。只有页面自然请求获得服务器认可、且返回身份与授权身份摘要一致才判定登录有效，不重新登录。连续7200秒采样，每60秒检查存活，每600秒重载原页面核对自然认证响应；结束后正常关闭、重开并再次认证。60秒烟测只能标记短测通过。

私有站点地址、身份规则和账号资料均只存在加密包内。公开artifact限定匿名JSON计数、布尔值、时长和异常类型，禁止上传截图、原始HTTP内容或整个资料目录。测试正常关闭后清理远端副本，并撤销临时secret及密文附件。平台自身会话到期或撤销仍可能导致失败；有限时长通过不能证明永远无bug、所有平台或所有设备都不会掉登录。

本机上述五类存储两轮已通过。平台登录仍受服务端有效期、主动撤销和安全验证控制；这些检查不能承诺某个真实平台永久不掉线，也不能代替该账号在通过原基线的第二台设备上的实际验收。
